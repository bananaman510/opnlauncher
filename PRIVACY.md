# Privacy

OpnLauncher is designed to keep launcher data on the user's device. This 0.1.0 development build has no analytics, telemetry, advertising, tracking pixels, crash-reporting service, launcher account, or automatic diagnostic upload. Optional playtime tracking is disabled by default and records game process sessions only in the local database.

## Network activity in this version

Opening the **Minecraft versions** section requests Mojang's official version manifest from `piston-meta.mojang.com`. Installing a version requests the selected version metadata and the client, library, logging, and asset files referenced by that metadata, including `libraries.minecraft.net` and `resources.download.minecraft.net`. These requests occur only when the user opens or refreshes the version list or starts an installation. Version downloads use HTTPS and verify upstream SHA-1 values and declared sizes where provided.

Opening **Mods** for an instance with readable Minecraft metadata searches Modrinth's documented API when Modrinth is selected. For a Horizon profile, the query uses Minecraft 26.3 and a Fabric filter so provider-compatible JARs can be reviewed. Selecting CurseForge makes requests to its official API only after the user enters a personal API key. That key is held in frontend memory for the current app session and sent only to CurseForge in the required request header; it is not saved to SQLite, WebView preferences, or logs, and is not sent to OpnLauncher. Mod files are fetched from the providers' supported HTTPS file hosts and checked against their published SHA-1 and/or file size before installation. Static resource inspection and conversion happen locally before launch and make no additional network request. If the user explicitly enables the experimental Horizon Fabric code bridge, OpnLauncher scans installed JAR metadata and class references, stages only allowlisted files in `.opnlauncher/fabric-code-bridge/`, starts a helper JVM, and forwards native client ticks over a loopback connection. Original JARs are not changed. OpnLauncher makes no network request for that bridge, but Java mods are not sandboxed: they can access files and network resources allowed to the user's account. Only enable mods the user trusts.

When the user opens **Switch version** for an older mod without a saved provider reference, or installs a project whose dependency may already exist in the selected instance, OpnLauncher calculates that JAR's SHA-1 locally and sends only the hash to Modrinth's version-by-file-hash endpoint to identify an exact matching release. The JAR contents are not uploaded. For a dependency with a saved provider reference, OpnLauncher requests that exact version's metadata from Modrinth or CurseForge, then checks its Minecraft and loader compatibility and verifies the local JAR's published SHA-1 and/or size before reusing it. CurseForge requests require the user's session-only API key as above.

Opening an instance's **Game setup** requests Mojang's official version manifest. Choosing Fabric or Forge also requests compatible loader versions from Fabric Meta (`meta.fabricmc.net`) or Forge Maven (`maven.minecraftforge.net`). Installing Fabric downloads its selected profile and required library artifacts from `maven.fabricmc.net` and, when referenced by the profile, `libraries.minecraft.net`. The launcher uses profile checksums and sizes when available; for coordinate-based profile entries it downloads the artifact's Maven SHA-1 sidecar from that same trusted host and enforces a file-size limit. Installing Forge downloads the official installer and its `.sha1` from Forge Maven, then runs that installer for the selected game folder. The Forge installer may make its own requests to Forge and Mojang metadata and library hosts while completing installation. These requests happen only after the user opens setup or chooses Install; they do not go through an OpnLauncher-operated server.

Choosing **Download files & prepare Horizon** requests Mojang's Minecraft 26.3 metadata and any missing official client, server, library, and asset files. When a Minecraft 26.3 folder is selected, matching local files are copied into Horizon's private cache only after SHA-1 and size checks against Mojang's metadata; the source folder is read-only to this operation. The same HTTPS and upstream integrity checks apply to downloaded files. OpnLauncher then runs the locally configured `horizon-prepare` tool against those local files; it does not pass an account token. Horizon client and preparation processes are given `HORIZON_TELEMETRY_URL=off` to disable Horizon telemetry and its play ping. Mojang receives the normal network connection details associated with requested metadata and files; no OpnLauncher service is involved.

Project artwork is loaded from `cdn.modrinth.com` and `*.forgecdn.net` when project cards or galleries are shown. These image requests reveal normal connection information such as the user's IP address to the relevant content host. The app permits images only from these hosts. Search text, the selected Minecraft version, and loader are sent to the chosen provider so it can return compatible results. Requests are not sent to an OpnLauncher-operated service.

Selecting **Continue with Microsoft** opens the system browser for Microsoft's OAuth authorization-code flow with PKCE. Microsoft, Xbox authentication/XSTS, and Minecraft services receive the requests needed to authenticate the account, check Java entitlement, and retrieve the game profile. The public client ID is stored in local app settings and sent to Microsoft as part of OAuth; OpnLauncher never asks for a password or client secret. The refresh token is stored in the Linux desktop Secret Service keyring, not SQLite, WebView storage, or launcher logs. It is sent back to Microsoft's token endpoint when a Java launch needs a refreshed session. Secure token storage is not yet implemented for Windows or macOS, so sign-in is unavailable there. Horizon launches continue to use local, unverified profiles and do not receive Microsoft tokens.

The UI uses system fonts and makes no remote font request. A launched Minecraft game is a separate process and may make its own requests according to that game's behavior; OpnLauncher does not intercept or firewall game traffic. OpnLauncher-operated servers are not part of the design.

## Local records

Automatic and manual installation searches check a fixed set of standard Minecraft and launcher-instance folders on this device. They read local version metadata only; they do not scan the whole disk or make network requests.

The app data directory contains the SQLite database, launcher logs, generated native libraries, optional playtime session records, and managed instance directories. Playtime sessions contain the instance ID, start/end timestamps, and duration; they are not associated with an account or transmitted. Turning tracking off preserves recorded sessions and stops the current session. A downloaded vanilla version is stored inside its new managed instance directory. Horizon's shared Minecraft 26.3 files and prepared resources are stored under the `horizon` subfolder; each Horizon profile's worlds, player data, and content mods stay in its instance folder. Registered external game directories are stored as paths and are not copied or modified by the general version browser. Game setup adds selected Minecraft and loader files to the chosen instance's game folder after the user chooses Install; conflicting existing files are left untouched. A registered folder may be shared by multiple instance records, and the UI warns when this is detected. The Forge installer may temporarily update `launcher_profiles.json`; OpnLauncher restores its prior contents (or removes the temporary file) after that installer exits. Loader installs do not remove worlds or mods. Installed mod provider IDs and version IDs are saved locally alongside filenames. Switching a version replaces only the selected mod file after verification; bulk deletion removes only the confirmed mod JARs selected in the Installed view. Diagnostic exports, when added, must be manual and redact authentication secrets.

Local developer profiles are unverified and are available in development and release builds. Their usernames and stable UUIDs remain in the local database and are not sent to an OpnLauncher service. They do not authenticate with Microsoft or verify game ownership. Microsoft account display names, UUIDs, and creation metadata are also stored in SQLite; access and refresh tokens are not.

The desktop WebView also stores local preferences on this device: theme, accent color, Microsoft public client ID, default Java path, default memory allocation, added Java executable paths, Horizon tool, resource, and selected Minecraft source paths, per-Horizon-profile window preferences, favorite instance IDs, the playtime chart range, and the currently selected instance and account. These preferences are not sent to an OpnLauncher server. Removing an instance from the launcher also removes its favorite marker; it does not delete its game files or worlds.
